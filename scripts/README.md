# Scripts

Dev and CI automation, one-shots, and the deterministic checks.

Executable helpers, not importable library code, except a module here that
another module outside `tests/` imports. That set is derived, never listed
here: `derived_features` in `tests/integration/test_reference_drift.py` reads
it from the import graph, and `docs/reference/features.md` carries a row for
each member (the CONVENTIONS §2 note says why each exists). A module a hook or
copier job imports must import under the 3.6.8 `python3` those run, which
cannot import `src/` (`docs/adr/keel/K-0012-child-process-environment-allowlist.md`);
the others hold a gate rule a command and its gate test share, not app logic.
Anything else reused by the app belongs in `src/`, not here. Project generation is `copier`-based (the repo root
is the template; see [ADR-K-0004](../docs/adr/keel/K-0004-project-templating-copier.md)).

## Deterministic checks (the template linter)

These scripts keep the template structurally honest — labeling, package
boundaries, the doc/code corpus, and the published contracts:

- `check_structure.py` — conventions validator (checks A–Z); `make check`.
- `jobs/check_corpus.py` — `wiki/corpus.json` integrity + build reproducibility.
- `agent_surface/generate_aad_schema.py --check` / `cdmon_sync.py --check` — contract drift.

Run them all with `make check-all` (or `make verify` for checks + lint +
types + tests). Each one's purpose, when to run it, and how to wire it as a
pre-commit / CI / scheduled hook is catalogued in
**[`docs/guides/deterministic-checks.md`](../docs/guides/deterministic-checks.md)**.
